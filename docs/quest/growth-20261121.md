## Webの計測

既存のGA4設定を利用する。新たに個人情報や問題への解答を送信しない。

- `quest_audience_route`: 学習目的の入口や教材詳細へのクリック。`audience`、`course`、`destination`、`page_path` を送る。
- `quest_store_click`: ストアリンクのクリック。既存の `store`、`placement`、`course` に、`audience`、`product_page`、`page_path` を加える。リンク固有の `data-course` を優先し、資格ハブの教材別クリックを区別する。

これらはWeb上のクリックであり、アプリのダウンロード・初回起動・教材学習を表す数値ではない。公開後は同じ期間・国・OSで、Search Consoleの表示とクリック、Webの目的別遷移、ストアの閲覧と初回ダウンロード、アプリの教材選択をそれぞれ確認する。既存中学受験のページ・検索語は別に追跡する。

## 検索とAI検索のための内容整合

新規ページには固有のtitle・description・canonical、HTMLで読める単元一覧とFAQ、内部リンク、WebPage・SoftwareApplication・BreadcrumbList・FAQPage・ItemListのJSON-LDを配置した。構造化データは表示内容に合わせ、評価件数や得点保証を新規ページに流用しない。FAQの構造化データは検索結果での特別表示を保証しない。

`sitemap.xml` に8URLを追加し、変更したトップと資格詳細のみlastmodを更新する。他のURLのlastmodは更新しない。`docs/quest/pages.json` にも同じ8URLを追加する。

`llms.txt`・`llms-full.txt` は補足情報として18教材の事実・日時・目的別URLを整合させる。GoogleのAI検索に専用のllms.txtが必須という主張や、これだけで順位が上がるという説明はしない。公開HTMLの内容・クロール可能性・内部リンクを中心に保つ。

## 再生成と検証

```sh
python3 scripts/quest/growth.py
python3 scripts/brand/check-static.py
node scripts/add-visitor-counters.mjs --check
node --check assets/quest/quest.js
node --check assets/quest/quest-growth.js
python3 scripts/quest/validate-growth.py
git diff --check
```

`validate-growth.py` はBeautifulSoupとPlaywrightを使用する。今回のMac環境では `/opt/homebrew/bin/python3.13` とインストール済みChromeで実行した。HTML本文・リンク・FAQ・単元の整合、既存本文の保全、320/390/1440pxの描画、画像、FAQ開閉、ストアクリックのGA4パラメータ、JavaScript無効時の内容を確認する。外部通信は遮断し、検証アクセスを実際のGA4へ送らない。

実行証跡は `output/quest-growth/validation.json` と同ディレクトリのスクリーンショットに保存する。今回WebKitの実行ファイルは未インストールだったため、Safari・実機iPhoneの検証とは表現しない。ブラウザが利用できない場合と、実際の検証失敗を区別して記録する。

変更後の処理を繰り返してもHTML・sitemap・llmsファイルに追加差分が出ないことを確認する。新規画像とソースのハッシュも記録し、独立レビューの後で公開する。公開後に重大な問題が見つかった場合は、この追加変更のcommitをrevertする。既存ページのURL削除や別作業の変更巻き戻しは行わない。
